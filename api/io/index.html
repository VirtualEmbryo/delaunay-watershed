    Files¶

    Read and write dw3d meshes: the .rec format with its metadata appendix, and .vtk/.vtu through meshio.

    A mesh is (points, triangles, labels): (n, 3) points, (m, 3) vertex indices and (m, 2) labels, the two regions each triangle separates (label 0 is the medium). The files store the points as given: these functions neither scale nor reorder their columns.

    The .rec reader and writer are copied from iorec, version 1.0.5. Matthieu Perez 2024

    load_rec_with_crop_faces(filename: str | Path) -> tuple[NDArray[np.float64], NDArray[np.int64], NDArray[np.int64], NDArray[np.bool_] | None]

    Read a rec mesh file and the crop faces its metadata appendix records.

    A file written by MeshReconstructionAlgorithm.save_to_rec_mesh, or by save_rec with crop_faces, holds its crop faces as the last block of triangle rows and records the block in the appendix as crop_faces = <first row> <count>. This reads that range back as a mask over the triangle rows, in the file's own row order.

    write_rec_appendix ¶

    write_rec_appendix(metadata: dict[str, Any], *, written_by: str) -> bytes

    Build the trailing .rec/.arec metadata appendix block.

    The block is a sequence of ASCII #-prefixed key = value lines, headed by the rec-appendix <version> line. It must be appended at the very end of the file: a trailing # block is invisible to every reader that predates it (both text and binary mode), since those readers read a count and then np.fromfile(..., count=n), which stops exactly there. A leading block breaks both readers. See tests/test_rec_appendix.py::test_legacy_reader_ignores_trailing_appendix.

    Parameters:

    Name Type Description Default
    metadata dict[str, Any]

    appendix fields, e.g. coordinate_frame, axis_order, spacing, spacing_unit, source_shape, crop_offset, crop_faces. Sequence-valued fields (spacing, source_shape, crop_offset, crop_faces) are written space-separated.

    		 required
    written_by str

    the dw3d version string that produced this file. Stamped by the writer -- the appendix is never hand-edited.

    		 required

    Returns:

    Name Type Description
    bytes bytes

    the ASCII appendix block (including a trailing newline), ready to be
    bytes

    concatenated onto the geometry bytes/text already written.

    		 required

Sequence-valued fields known to the schema are parsed into tuples (spacing of float; source_shape, crop_offset and crop_faces of int), and resampled_spacing into a float; every other key is kept as a raw string, never dropped, so a future rewrite can carry it forward.

    load_rec_appendix ¶

    load_rec_appendix(filename: str | Path) -> dict[str, Any] | None

    Read the trailing metadata appendix from a .rec/.arec file, if present.

    Works uniformly for text- and binary-mode files: the appendix is located by finding the last # rec-appendix marker in the file. It is written only ever as the literal first line of the trailing appendix block (see write_rec_appendix), so its last occurrence marks the start of the block -- note that binary-mode payloads have no guaranteed newline before this marker, so the search cannot require one.

    Parameters:

    Name Type Description Default
    filename str | Path

    the path to the file on disk.

    		 required

    Returns:

    Type Description
    dict[str, Any] | None

    dict[str, Any] | None: the parsed appendix fields (see parse_rec_appendix), or None if the file has no appendix. A None return must be treated by the caller as coordinate_frame == "unknown", never as isotropic spacing -- a legacy file's absent appendix carries no information about spacing at all.

    save_rec ¶

    save_rec(filename: str | Path, points: NDArray[float64], triangles: NDArray[int64], labels: NDArray[int64], binary_mode: bool = False, metadata: dict[str, Any] | None = None, crop_faces: NDArray[bool_] | None = None) -> None

    Save a rec mesh file at filename. Binary or text mode are available.

    Binary mode is more compact but might not be universally understood. Its layout, in the machine's byte order (little-endian on x86 and ARM), is: the number of points (uint64); the points, 3 float64 each; the number of triangles (uint64); per triangle, its 3 vertex indices (int64) then its 2 labels (int32). The points are always written as float64, the dtype load_rec reads, whatever their dtype in memory (before 0.7.0 they were written in their own dtype, so float32 points did not read back). The text layout is the point count, one x y z line per point, the triangle count, and one v0 v1 v2 label1 label2 line per triangle. Either layout may be followed by the metadata appendix.

    Parameters:

    Name Type Description Default
    filename str | Path

    where to save the mesh file.

    		 required
    points NDArray[float64]

    (n, 3) mesh points, written as given.

    		 required
    triangles NDArray[int64]

    (m, 3) mesh triangles (topology).

    		 required
    labels NDArray[int64]

    (m, 2) the two regions each triangle separates.

    		 required
    binary_mode bool

    Choose binary mode. Defaults to False.

    		 False
    metadata dict[str, Any] | None

    appendix fields (coordinate_frame, axis_order, spacing, spacing_unit, source_shape, crop_offset, ...). Defaults to None, which writes nothing extra -- byte-for-byte the same file as before this option existed. When supplied, a trailing metadata appendix is appended after the geometry data; see write_rec_appendix.

    		 None
    crop_faces NDArray[bool_] | None

    (n_triangles,), True on the crop faces (see dw3d.crop_faces). When given, the crop faces are written as the last block of triangle rows (the other rows first, both blocks in their original order) and the appendix records crop_faces = <first row> <count> (<count> may be 0), so the file's rows are in a different order from the arrays passed in. A reader that ignores the appendix still reads a valid mesh, in which the crop faces look like contact with the medium; load_rec_with_crop_faces reads them back. Defaults to None, which writes the file as before this option existed.

    		 None

    Raises:

    Type Description
    ValueError

    if crop_faces is not a boolean array with one entry per triangle.
